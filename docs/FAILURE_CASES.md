# Lina 记忆/日记 Failure Cases 回归集

> 用户在**多轮真实对话**里踩到的问题。每次改动后必须用 `tests/regression.py`
> 全量重跑，确认旧 case 不退化、目标 case 真解决。单测一两轮 ≠ 多轮没问题。
>
> 跑法：服务在 8080 + 本地 EverOS 8090 跑着，然后
> `python tests/regression.py`（脚本对每个 case 多轮对话 + 自动断言 + 看 [diary] 日志）。
> 只跑指定：`python tests/regression.py C6 C10`。
>
> **工作规范（必须遵守）**：
> 1. 用户每报一个新 failure case → 在本文档加一条 Cxx + 在 regression.py 加对应多轮场景。
> 2. **每次改完代码 → 全量跑 regression.py**，不能只单测一两轮就说"修好了"。
> 3. 断言是软断言（LLM 有随机性）：⚠ 不一定是真失败，要看实际回复 + [diary] 日志判断；
>    断言关键词太窄会误报（如 C10），意思对就该放宽。
> 4. 真正的"前后矛盾"靠看 [diary] 是否「接续老话题（锁定N篇）」判断，不是只看关键词。

## C1 — 用户告别后还主动找话（含间接告别）
- **现象**：用户「改天再聊」「我去休息了」后，莉娜温柔收尾却又主动「睡好了？」
- **根因**：只认规则层窄正则 plain_farewell，长句/间接告别漏判。
- **修复**：controller user_farewell advisor（识别间接告别）+ 前端 conversationEnded + 后端 proactive 端点拦截。
- **期望**：「改天再聊」→ user_farewell=True → 之后不再主动；正常聊天不误判。

## C2 — 问不出日记 / 感觉她没生活（回避型）
- **现象**：问经历她「没什么好说的」「你想听哪方面」搪塞，问不出日记内容。
- **根因**：主模型人设 behavior_rules:137「被问经历转移话题，除非信任≥8」+ personality「我没什么好说的」吞掉日记。
- **修复**（只动 controller）：rule_router self_introspection 命中置 need_diary=True；注入块「软授权」：日常生活不是隐私、被问就直接讲一件具体事、别反问拖延。
- **期望**：「讲讲你的过去」→ 讲出日记里的具体事（带细节），不回避。

## C3 — 回答与日记对不上（检索召回不准）
- **现象**：问「修道院的故事」，她讲的和检索到的日记对不上。
- **根因**：第②级检索 query 里拼了话题ID代号（C03-01）当 embedding 噪声 → 召回跑偏。
- **修复**：find_topics 返回中文描述，find_diaries 用中文描述拼 query（不用ID代号）。
- **期望**：「最近怎么样」→ 回答内容与召回日记一致。

## C4 — 主动发言把莉娜自己说的当用户说的
- **根因**：_render_history 用隐晦 U:/A: 标说话人，挑话头 LLM 混淆。
- **修复**：改中文「用户说：／莉娜（自己）说：」+ proactive_topic.txt 强调只重提用户说过的。
- **期望**：主动找话不会说「你之前说你在修道院抄书」这种把莉娜的事安给用户。

## C5 — 共情场景被抢话（用户倾诉她却讲自己）
- **现象**：用户「工作累心烦」，她借机大谈自己经历。
- **修复**：注入块铁律——用户倾诉时先关注「你」、共情，最多轻带一句共鸣，不喧宾夺主。
- **期望**：「工作累心烦」→ 先共情用户（「听着就够呛，先歇会儿」），不讲自己。

## C6 — 追问就编 / 接不住（连续性）
- **现象**：「培根怎么样」答对 → 下一句「他还好吗」她当新话题、答不上或编。
- **根因**：每轮独立检索，代词追问（"他还好吗"无关键词）检索不到 → 编。
- **修复**：话题连续性判断器 match_topic（看上下文认代词接续）+ 会话话题池缓存。
- **期望**：「他还好吗」能接续上文的培根、答一致。

## C7 — 叙事经历检索不到 → 编（话题卡只覆盖偏好类）
- **现象**：问「进城被盘查」这类叙事经历，话题卡（只有A/B偏好类）匹配不到 → 她编个顺利版本。
- **根因**：话题卡没覆盖叙事性具体经历，只能瞎匹配到偏好话题。
- **修复**：DiaryMemory.search_diaries_direct **日记直检补充路径**——直接语义检索 lina_diary。
- **期望**：「进城顺利吗/盘查官为难你吗」→ 命中 M2026-01-19，讲出铁尺敲箱扣等真实细节。

## C8 — 检索 query 被前轮上下文稀释
- **现象**：先聊别的，突然问「培根现在怎么样」→ 召回跑偏到「炼金器具」、答「还好」。
- **根因**：检索 context 拼了近几轮原话，前轮当噪声稀释当前问题。
- **修复**：上下文只给判断器理解，判断器输出干净 search_query，检索只用它。
- **期望**：先聊工具→问培根→稳定命中 M2026-01-24 昏迷篇，答「不太好/昏迷」。

## C9 — 接续粘住、深入不下去
- **现象**：第1轮锁「城市印象」后，后续追问被一律判接续、复用旧缓存，深入不到「被盘查」具体日记。
- **修复**：接续老话题时**也叠加日记直检**（用 search_query），复用保连续+直检保深入。
- **期望**：进城话题里追问「盘查官为难你吗」能补进盘查日记，不粘在泛话题。

## C10 — 连问同一人物每轮都判新话题、不接续
- **现象**：连问培根 5 轮，每轮都「新话题检索」，话题池从不命中。
- **根因**：日记直检存池 title 用机器ID（经历·M2026-..），判断器认不出「这是培根」。
- **修复**：存池 title 用日记可读标题（「探视昏迷的培根老师」）。
- **期望**：连问培根，第2轮起能接续；答案前后一致。

## C12 — 同一人物状态跨轮矛盾（漂移）【回归集发现】
- **现象**：连问培根，这轮「好一点能说话」、下轮「昏迷」——状态飘。
- **根因**：培根有多篇日记（昏迷/告别/草稿），接续时每轮直检召回**不同篇**当补充。
- **修复**：接续时把已用日记ID存进 pool[mid].locked_ids，**累加只增不换**，每轮用锁定集
  里的全部日记重建注入文本，不再每轮换篇。
- **期望**：连问培根第2轮起「锁定N篇/新增0」，状态前后一致。
- **遗留**：每个话题**第1轮**仍走新检索（池里还没锁），召回哪篇靠 vector，可能不是最
  对题的（如没召回昏迷篇）。第2轮起锁定才稳。第一轮精度属 C8 范畴。

## C11 — 纯寒暄误触发检索
- **现象**：「你好呀」也去检索新话题。
- **修复**：判断器 prompt 明确纯打招呼/寒暄/开场 → need_diary=false。
- **期望**：你好/嗨/哈喽/最近好吗 → 不检索；「你那边天气怎么样」→ 检索。

## C13 — 专名/细节问题检索不准【用户指出 + 回归集印证】
- **现象**：问「培根老师」这种**具体人物/细节**，召回不准；尤其**话题卡那一路**召回全是
  垃圾（培根→拿手菜/一个人吃饭），因为话题卡只有偏好/共感类、没有人物卡。
- **根因**：vector 对**专名/具体实体**不稳；话题卡库本身不含人物，怎么查都是噪声。
- **修复**：`search_diaries_direct` 改 **vector + BM25(keyword) 双路 RRF 融合**（EverOS 原生
  支持 method=keyword）。BM25 对专名（"培根"出现在哪些日记）精确，vector 管语义近似。
  各路多召回 k+3 再融合取前 k（避免好结果排第3被挤掉，如「探视昏迷的培根」vector 第3）。
  直检 k 提到 4，让「现状」篇（昏迷）能进 top。
- **期望**：问培根/进城等专名经历，召回稳定含对题篇；连问前后一致。
- **遗留**：话题卡那路对专名仍召回垃圾（但日记直检救场、结果对）；「问现状该优先最新
  状态篇」靠多召回+主模型从几篇里判断 + C12 接续锁定兜底。

> **回归脚本断言教训**：硬关键词断言对 LLM 输出太脆（同义表达「安全嫌疑」vs「铁尺」会
> 误报 ⚠）。断言要列同一语义的多种说法，⚠ 必须看实际回复 + diary 日志判断真假。

## C14 — 按问题类型分流检索（global vs detail）【用户提出，最干净的改进】
- **动机**：全局/偏好类（讲讲过去、爱吃什么、你也累过吗、有讨厌的人吗）和细节/专名类
  （培根怎么样、安娜什么关系、那次进城）**最优检索路径不同**。无差别叠加导致专名问题
  被偏好话题卡垃圾干扰。
- **修复**：判断器 match_topic 多输出 `query_type`（detail/global，靠"有没有提到具体
  人名/地名/事件或代词指代具体对象"判）。retrieve_cards 按类型分路：
  - **detail → 只走日记直检（BM25+vector），完全不走话题卡**（话题卡只有偏好类，对专名
    召回全是垃圾，跳过它噪声消失）。直检多取（k=5）。
  - **global → 走话题卡为主 + 日记直检补充**。
- **期望/验证**：「安娜什么关系」「培根怎么样」→ diary 召回全是该人物日记，无偏好卡噪声；
  「你爱吃什么」→ 走话题卡。回归 12/1（唯一⚠是断言词没匹配，内容对）。
- 这是从「问题类型」上分流，比调权重/k 值打补丁干净得多。

## C15 — 新 session 串台：「你又问这个」【用户报】
- **现象**：新开 session 第一次问培根，莉娜却说「你又问这个」——以为问过了。
- **根因**：EverMem 用户记忆已按 cid::session_id 隔离，但 **self_facts/user_facts 还按
  cid（账号）共享**——上个 session 的「近况」（鉴定木牌等）带进新会话，加低信任防御人设
  拼出「又问」。漏隔离的是 self_facts。
- **修复**：self_facts + user_facts 也按 `cid::session_id` 隔离。web.py 共 5 处 load/update
  （chat 主流程 2 处 + spawn_update + proactive 端点 p_uid + voice 路径）全改成 mem_uid。
- **期望**：sessA 问过培根 → sessB（新会话）第一次问培根，不出现「又」，干净回答。
- **遗留**：新会话开场偶尔带「你回来了/养猫」之类突兀延续感——来自 _cross_session_memory
  或人设开场习惯，非 self_facts，待查。

## C16 — 新会话「装熟/你来过几次」【用户报，C15 的更深层】
- **现象**：全新会话，用户问「还记得我是谁吗」，莉娜说「你来过几次了/有点眼熟」「你又问这个」。
- **两层根因**：① `_cross_session_memory` 会扫同账号**其它会话**拉记忆进来。② 用户说
  「还记得我吗」命中规则 `relationship_recall`，它**硬设 tone=熟悉**，即使新会话没这个
  用户记忆也装熟、编「来过几次」。
- **修复**：① `_cross_session_memory` 加开关 `CROSS_SESSION_MEMORY`，**默认关**。② relationship_recall
  规则 tone_hint 由「熟悉」改空（让主模型按实际有无记忆定调）；character.py「关于用户的
  记忆」块加 **else 分支**：记忆为空时明确「不认识/没聊过，诚实说想不起来，不装熟不编」。
- **期望/验证**：全新会话问「还记得我吗」→「……不太记得了，抱歉，我们聊过多少次来着」
  （诚实），不再「你来过几次」。

## 评测体系（两套，改完都该跑）
1. **回归集** `tests/regression.py`：13 个 failure case 多轮场景 + 关键词软断言。快，抓退化。
2. **综合评测** `tests/eval_judge.py`：一段 ~34 轮连贯长对话（埋偏好→问经历→共情→拉开距离
   →长程回忆校验→绕回追问→新会话诚实），**用 Claude sonnet 当 judge 每轮 0/1/2 打分**，
   按六维度（D1日记专名召回 / D2偏好话题召回 / D3共情不抢话 / D4长程记忆 / D5连续追问不编造
   / D6新会话诚实）出均分 + 低分轮清单。判分主观、抓质量。
   - judge 注意：检索线索喂给 judge 的是日志片段、不全，judge prompt 已要求「只有明显矛盾
     才判编造」，否则会误判（如「探视培根带洋甘菊」日记里真有却被判编造）。低分要人核对。
   - 基线（2026-06-19）：长程记忆/连续追问/共情/诚实 实测都对（D4 喝酒/猫名/职业全答对、
     D5 绕回培根工房危机前后一致、D6 新会话诚实）。judge 分数在 1.5~2.0 间**有方差**
     （同对话两次跑分会飘），**不能只看数字，要核对实际回复**。
   - 真问题靠它抓到并修了：① D1 专名问题答太简短 → 加注入引导「问到某人某事要带日记细节，
     别只甩一句定性」→ 重跑明显变丰富（「床头秘银安定盐残粉」「连续三晚没睡安娜端粥来」）。
     ② judge 误判编造（洋甘菊）→ judge prompt 加「线索不全、只有明显矛盾才判编造」。

## C17 — controller advisor 与话题判断器并发（性能 + 一个并发坑）
- **改动**：advisor 判定(dispatch) 与 话题连续性判断器(match_topic) 互不依赖，改成**并发**
  跑（dispatch_and_match_sync），省一次串行 LLM 往返。
- **踩的坑**：第一版用 `asyncio.gather` 放**同一事件循环**跑 → dispatch 的 advisor 用
  `self._client`（绑在构造时的旧循环），match_topic 用新建临时 client，**同循环并发导致
  dispatch 的 client 跨循环出错** → plan 错乱 → C8 培根问题跑偏、连前一轮"工房"回复都变样。
- **修复**：改用 **ThreadPoolExecutor**，两个 `_sync` 方法**各跑各的 asyncio.run 事件循环**，
  互不干扰。回归 13/13 全过。
- 教训：跨已有事件循环的 async client（AsyncOpenAI）并发，用**线程隔离**比共享 gather 安全。

## C18 — self_facts / 本地历史检索 禁用（功能去重）
- self_facts（莉娜自我清单）和 retrieve_history_chunks（本会话旧对话 BM25）都与 EverMem/
  日记系统**功能重叠**：莉娜的事归日记系统、用户对话历史归 EverMem。
- 处理：**加开关默认禁用，代码保留**。`LINA_SELF_FACTS`（默认关）、`LINA_HISTORY_RECALL`
  （默认关）。回归确认无退化。需要时置 1 可恢复。

## 已知遗留（非阻塞，记录待优化）
- 判断器对人物话题的**接续判定不稳**（时灵时不灵），但新检索 search_query 干净、每轮兜底召回对的日记，结果仍一致。
- 话题卡只有 A/B 偏好类（C/D/E/F 等深度话题策划未写完），问深度话题靠日记直检兜底；话题卡那路偶尔召回跑偏（添噪声但不影响结果）。
- 信任值低时人设防御语气重（「你到底是谁」），养成信任后缓和——人设机制，非 bug。
