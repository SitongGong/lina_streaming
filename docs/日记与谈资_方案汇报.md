# 莉娜「日记 + 谈资」记忆系统 —— 方案汇报

> **一句话**：给数字人莉娜接上「自己的人生」——她有连贯的日记和成体系的谈资话题，
> 用户聊到时她**调出真实经历来回答、而不是临时编造**；同时**记住用户、共情用户、
> 多轮追问前后一致**。全部在主模型人设之外的「记忆控制层」实现，不动人格底线。

---

## 一、要解决的核心问题

让莉娜像一个**有生活、有连续记忆的人**。四个硬要求：

1. **不编造**：问她经历（培根老师怎么样、那次进城），调**真实日记**作答，不现编。
2. **共情 + 记住用户**：用户讲自己的事，先关注用户、并跨多轮记住他的偏好。
3. **多轮一致**：连续追问（"他还好吗""后来呢"）能接住、前后不矛盾。
4. **不碰人设**：以上全在外围控制层做，**主模型人格 prompt 一行不动**。

---

## 二、核心数据资产

| 资产 | 规模 | 说明 |
|---|---|---|
| 莉娜日记 | **180 篇**（2026 上半年，每天一篇） | 结构化「记忆条目」：时间/地点/人物/正文/情绪/**关联话题** |
| 谈资话题卡 | 共 1565 个，**已写完整 213 个** | 策划写的「话题说明书」：开场句/可追问/莉娜观点/共情方式/信任门槛/**关联日记ID** |

> 话题↔日记是**多对多**（一篇日记关联多个话题，一个话题对应多篇日记），这层关系
> 由策划在话题卡的「日记索引」里用精确日记ID写好了——是我们精确检索的基础。

## 三、整体流程（一轮对话）

```
                       用户说一句话
                            │
              ┌─────────────┴──────────────┐
              ▼                             ▼
   ① 话题连续性判断器(轻量LLM)         ② 用户记忆检索(EverMem云)
      看「本句 + 近几轮上下文」            按 会话ID 检索"用户说过的事"
      产出4个决策：                       （与日记线互相独立、每轮都走）
      · need_diary 要不要调日记?                │
      · query_type  细节(detail)/泛问(global)?   │
      · 新话题 还是 接续旧话题?                   │
      · search_query 干净检索词                  │
              │                                  │
              ▼                                  │
   ③ 按决策检索莉娜日记/谈资(本地EverMemOS)        │
      ├ 接续旧话题 → 复用本会话缓存+锁定的日记(保一致)
      ├ 新·细节类  → 精确检索日记(BM25+向量)
      └ 新·泛问类  → 检索话题卡(带谈资指引)+日记
              │                                  │
              └──────────────┬───────────────────┘
                             ▼
        ④ 把【真实日记/话题卡指引】+【用户记忆】注入
           （注入到主模型人设之外的"记忆区"，人设prompt不动）
                             ▼
                  ⑤ Claude(sonnet) 生成回复
                             ▼
                  ⑥ 本轮对话写入用户长期记忆(按会话隔离)
```

**三套记忆并行、各管一摊、互不串台：**
| 记忆 | 内容 | 隔离 |
|---|---|---|
| 用户记忆 | 用户是谁、说过什么 | **按会话隔离**（新对话=全新开始） |
| 莉娜人设 | 世界观、性格（静态） | 全局 |
| 莉娜日记/谈资 | 她的生活经历（本方案核心） | 全局（她的人生对谁都一样） |

## 四、技术攻关亮点（最近几次迭代的重点）

> 下面每条都是真实踩过的坑 + 我们的解法，是这套系统区别于"简单 RAG"的地方。

### 攻关 1：按问题类型分流检索 —— 解决"召回不准/被噪声污染"
**问题**：问"培根老师怎么样"这种**具体人物**，话题卡（偏好/共感类）匹配进来的全是
"拿手菜""一个人吃饭"等垃圾，污染回答。
**解法**：判断器先分类——
- **细节/专名类**（培根、安娜、某次事件）→ **只精确检索日记**，向量 + 关键词 BM25
  双路（BM25 对人名等专有词精确命中），**不走话题卡**，噪声清零。
- **泛问/偏好类**（爱吃什么、讲讲经历）→ 走**话题卡**（里面有现成的开场句、共情指引）。

### 攻关 2：话题连续性 + 会话锁定 —— 解决"追问就编 / 前后矛盾"
**问题**：①"他还好吗"这种代词追问没有关键词，检索不到 → 莉娜现编。②培根有多篇日记
（昏迷/告别/草稿），不同轮检索到不同篇 → 这轮说昏迷、下轮说好转，**自相矛盾**。
**解法**：
- 判断器靠**上下文**识别"这是在接续上一个话题"（哪怕只说"他还好吗"），并把代词补全成
  干净检索词（→"培根老师的近况"）。
- 一个话题聊过后，把它对应的日记**缓存+锁定**在本次会话里，后续追问/绕回**复用同一批**，
  状态前后一致，不再漂移。

### 攻关 3：双轨记忆 + 会话隔离 —— 解决"串台/装熟"
**问题**：新开一个会话，莉娜却说"你来过几次了/又问这个"——把别的会话、别的用户的痕迹
带进来了。
**解法**：用户记忆、莉娜自我状态全部**按会话ID隔离**；跨会话记忆默认关闭。
**新会话 = 完全干净的莉娜**：陌生用户问"还记得我吗"，她**诚实说想不起来，绝不装熟编造**。

### 攻关 4：共情优先，不抢话
**问题**：用户倾诉（"工作累、被否定"），莉娜借机大谈自己的经历。
**解法**：注入规则明确——用户倾诉时**先关注用户、共情**，自己的经历最多轻带一句做陪伴，
不喧宾夺主。

### 攻关 5：写 md 建索引，不依赖大模型 —— 低成本、可扩展
日记/话题都是 markdown，由 EverMemOS 用 **embedding（本地 Qwen3-Embedding-4B）**
自动建索引，**建索引全程不用大模型**。莉娜回复才用 Claude。意味着**日记规模做到数千篇
也扛得住、成本可控**。

## 五、检索决策详图（攻关1+2的落地）

```
判断器输出 →  need_diary?
                │否→ 不调日记（纯寒暄/纯功能问答，如"几点了"）
                │是
                ▼
        是否接续会话里聊过的旧话题?
         │是→ 复用该话题【锁定的日记】+本轮再补检索 → 前后一致
         │否（新话题）
         ▼
      query_type 是哪类?
       ├ detail(专名/细节) → 日记库(BM25+向量) ……精确命中"培根/安娜"
       └ global(泛问/偏好) → 话题卡(谈资指引)+日记 ……自然有质感
                ▼
         命中→注入真实内容；未命中（话题没写完）→ 回退人设/老实说不清楚，绝不编
```

## 六、效果（已做大规模自动化测试）

建了两套自动评测，**每次改动都全量重跑**，不靠人工逐句看：
- **回归测试**（`tests/regression.py`）：16 个真实问题场景（多轮），抓功能退化。
- **综合评测**（`tests/eval_judge.py`）：一段 30+ 轮连贯长对话，**用 Claude 当裁判
  按 6 个维度自动打分**（日记召回/偏好召回/共情/长程记忆/连续性/诚实）。

**实测：**
| 能力 | 结果 |
|---|---|
| 长程记忆（隔 20+ 轮还记得用户职业/宠物/忌口） | ✅ 准确 |
| 连续追问前后一致 | ✅ 不矛盾 |
| 共情用户、不抢话 | ✅ |
| 新会话诚实、不装熟 | ✅ |
| 专名问题调真实日记（培根昏迷、安娜端粥、进城被盘查） | ✅ 有细节不编造 |

**实测对话片段（连续追问培根，全部来自真实日记、前后一致）：**
> 用户：你跟培根老师什么关系 → 莉娜：他是我老师……把我带进这行的人。不过他现在身体不太好。
> 用户：他现在还好吗 → 莉娜：不太好……一直昏迷着。我上次去看他，床头药碗里还有秘银安定盐的残粉。
> 用户：你上次去看他是什么时候 → 莉娜：清晨，雨刚停。他那天醒了一会儿，叮嘱我回山谷继续誊抄那本稿子。

## 七、对海量日记的可扩展性

未来日记规模会很大（6–18 岁、每天一篇 ≈ 数千篇）。本方案**天然能扛**：检索始终在
"话题层（数百个）+ 按精确ID取日记"，**不会因为日记变多而变慢、变乱**；建索引不用大模型。

---

## 八、当前限制（坦诚）

1. 话题卡写完 213/1565（策划进行中）；**没写完的话题暂不参与检索**，问到时回退人设或
   老实说不清楚（不会乱编），策划补全后增量导入即可。
2. 日记目前只覆盖近半年，**童年/更久远经历**靠人设回答。
3. 信任值低时对陌生用户偏防御（人设设定），随互动升温缓和。
4. 判断器是轻量 LLM，极少数边界判错类型时有日记直检兜底，不影响主流程。
